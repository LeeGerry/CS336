## 一、基础：数学、训练与分词

- **向量（vector）**：一排有序的数字，可以看成高维空间中的一个点或一个箭头。见 [第 0 章](./ch00-primer)
- **矩阵乘法（matrix multiplication）**：一次性算很多个点积，是神经网络里最主要的计算，$m\times k$ 乘 $k\times n$ 约需 $2mkn$ 次浮点运算。见 [第 0 章](./ch00-primer)
- **浮点运算次数（FLOPs）**：衡量计算量的单位，训练一个 Transformer 大约需要 $6ND$ 次（$N$ 参数量、$D$ token 数）。见 [第 0 章](./ch00-primer)
- **梯度（gradient）**：损失对每个参数的偏导数组成的向量，指向「损失上升最快」的方向。见 [第 0 章](./ch00-primer)
- **梯度下降（gradient descent）**：沿着梯度的反方向一小步一小步地调整参数，让损失变小。见 [第 0 章](./ch00-primer)
- **随机梯度下降（SGD, Stochastic Gradient Descent）**：每次只用一小批数据估计梯度再更新，比用全部数据快得多。见 [第 0 章](./ch00-primer)
- **学习率（learning rate）**：每一步沿梯度走多远的系数，太大会发散，太小会学得极慢。见 [第 0 章](./ch00-primer)
- **批大小（batch size）**：一次参数更新用多少条样本，越大梯度估计越准，但显存和通信开销也越大。见 [第 0 章](./ch00-primer)
- **Adam / AdamW 优化器（Adam / AdamW optimizer）**：为每个参数记住梯度的滑动平均和平方滑动平均来自适应调步长，AdamW 还把权重衰减单独处理，是 LLM 的默认优化器。见 [第 0 章](./ch00-primer)
- **softmax**：把一组任意实数「打分」变成加起来为 1 的概率分布，大的更大、小的更小。见 [第 0 章](./ch00-primer)
- **温度（temperature）**：softmax 前把打分除以的数，温度高输出更随机，温度低更确定。见 [第 0 章](./ch00-primer)
- **交叉熵损失（cross-entropy loss）**：正确答案概率的负对数，语言模型训练时最小化的就是它。见 [第 0 章](./ch00-primer)
- **困惑度（perplexity）**：交叉熵取指数，直觉是「模型平均在几个候选词之间犹豫」，越低越好。见 [第 0 章](./ch00-primer)
- **嵌入（embedding）**：把一个离散的编号（如 token ID）查表变成一个稠密向量。见 [第 0 章](./ch00-primer)
- **多层感知机（MLP, Multi-Layer Perceptron）**：线性层和非线性激活函数交替堆叠的网络，Transformer 中的前馈层就是它。见 [第 0 章](./ch00-primer)
- **反向传播（backpropagation）**：从损失出发沿计算图反向逐层应用链式法则，一次算出所有参数的梯度。见 [第 0 章](./ch00-primer)
- **语言模型（language model）**：给定前文、预测下一个 token 概率分布的模型。见 [第 1 章](./ch01-overview-tokenization)
- **自回归（autoregressive）**：一次生成一个 token，再把它接到输入后面继续生成下一个。见 [第 1 章](./ch01-overview-tokenization)
- **token（词元）**：模型处理文本的最小单位，可能是一个字、一个子词或一个字节片段。见 [第 1 章](./ch01-overview-tokenization)
- **分词器（tokenizer）**：把字符串切成 token 并映射成整数 ID 的程序，像是文本的「编码格式」。见 [第 1 章](./ch01-overview-tokenization)
- **字节对编码（BPE, Byte Pair Encoding）**：从字节开始反复把最常一起出现的一对合并成新 token，主流的分词算法。见 [第 1 章](./ch01-overview-tokenization)
- **词表（vocabulary）**：分词器认识的全部 token 的集合，大小通常是几万到几十万。见 [第 1 章](./ch01-overview-tokenization)
- **einops**：用「字母表达式」描述张量维度重排的库，比手写 view / transpose 更不易出错。见 [第 2 章](./ch02-pytorch-resource)
- **bf16（bfloat16）**：16 位浮点格式，指数位和 fp32 一样多、精度更低，训练大模型的常用精度（混合精度训练中与 fp32 搭配使用）。见 [第 2 章](./ch02-pytorch-resource)
- **模型 FLOPs 利用率（MFU, Model FLOPs Utilization）**：实际有效算力占硬件峰值算力的比例，衡量训练跑得「满不满」。见 [第 2 章](./ch02-pytorch-resource)

## 二、架构：Transformer 及其变体

- **Transformer**：以自注意力和前馈网络为基本模块堆叠而成的架构，当今几乎所有大模型的骨架。见 [第 3 章](./ch03-architectures)
- **自注意力（self-attention）**：序列里每个 token 用自己的查询（query）去和其他 token 的键（key）比相似度，再按权重汇总它们的值（value）。见 [第 3 章](./ch03-architectures)
- **多头注意力（MHA, Multi-Head Attention）**：并行跑多组小注意力，每组关注不同的关系，再拼接起来。见 [第 3 章](./ch03-architectures)
- **因果掩码（causal mask）**：让每个位置只能看到它之前的 token，防止训练时「偷看答案」。见 [第 3 章](./ch03-architectures)
- **残差流（residual stream）**：每层的输出都加回到一条贯穿全网的主干向量上，信息和梯度都沿它流动。见 [第 3 章](./ch03-architectures)
- **前馈网络（FFN, Feed-Forward Network）**：注意力之后对每个 token 单独做的两层（或门控三层）MLP。见 [第 3 章](./ch03-architectures)
- **层归一化（LayerNorm）**：把一个向量减均值、除标准差再缩放，稳定训练。见 [第 3 章](./ch03-architectures)
- **RMSNorm**：只除以均方根、不减均值的简化版 LayerNorm，更省也一样好用。见 [第 3 章](./ch03-architectures)
- **门控线性单元 / SwiGLU（GLU / SwiGLU）**：前馈层里让一路输出去「开关」另一路的结构，SwiGLU 是现代 LLM 的标配。见 [第 3 章](./ch03-architectures)
- **位置编码（positional encoding）**：告诉模型每个 token 在序列中的位置，因为注意力本身不区分顺序。见 [第 3 章](./ch03-architectures)
- **旋转位置编码（RoPE, Rotary Position Embedding）**：按位置把查询和键向量旋转不同角度，使注意力分数只取决于相对距离。见 [第 3 章](./ch03-architectures)
- **分组查询注意力（GQA, Grouped-Query Attention）**：多个查询头共享一组键值头，大幅缩小推理时的 KV cache。见 [第 3 章](./ch03-architectures)
- **KV 缓存（KV cache）**：生成时把已算过的键和值存起来，下一个 token 不必重算整个前文，像图片缓存一样以空间换时间。见 [第 3 章](./ch03-architectures)
- **z-loss**：惩罚 softmax 归一化项过大的辅助损失，防止 logit 越长越大导致训练不稳定。见 [第 3 章](./ch03-architectures)
- **上下文长度（context length）**：模型一次能看到的最大 token 数，注意力的计算量随它平方增长。见 [第 4 章](./ch04-attention-alternatives)
- **线性注意力（linear attention）**：利用矩阵乘法结合律把注意力的平方复杂度降成线性，本质上等价于一个 RNN。见 [第 4 章](./ch04-attention-alternatives)
- **Mamba / 状态空间模型（state space model）**：用一个不断更新的固定大小状态来记忆历史的序列模型，推理时显存不随长度增长。见 [第 4 章](./ch04-attention-alternatives)
- **混合专家（MoE, Mixture of Experts）**：把前馈层换成很多个「专家」，每个 token 只激活其中几个，总参数大而单次计算小。见 [第 4 章](./ch04-attention-alternatives)
- **路由器 / top-k 路由（router / top-k routing）**：给每个 token 打分并挑出得分最高的 k 个专家去处理它。见 [第 4 章](./ch04-attention-alternatives)
- **负载均衡损失（load balancing loss）**：鼓励 token 均匀分配到各专家的辅助损失，避免少数专家累死、其余闲置。见 [第 4 章](./ch04-attention-alternatives)

## 三、系统：GPU、kernel、并行与推理

- **GPU（Graphics Processing Unit）**：拥有成千上万个简单计算单元、追求吞吐量的处理器，深度学习的主力硬件。见 [第 5 章](./ch05-gpus-tpus)
- **TPU（Tensor Processing Unit）**：Google 专为矩阵运算设计的加速器，以大块矩阵乘法单元和高速片间互连为特色。见 [第 5 章](./ch05-gpus-tpus)
- **流式多处理器（SM, Streaming Multiprocessor）**：GPU 里的「核」，每个 SM 独立调度和执行一批线程。见 [第 5 章](./ch05-gpus-tpus)
- **高带宽显存（HBM, High Bandwidth Memory）**：GPU 的主显存，容量大但相对片上内存慢得多。见 [第 5 章](./ch05-gpus-tpus)
- **共享内存 / SRAM（shared memory）**：SM 内部又小又快的片上存储，高效 kernel 的关键就是把数据搬进这里反复用。见 [第 5 章](./ch05-gpus-tpus)
- **Tensor Core**：GPU 里专门做矩阵乘法的硬件单元，速度远超普通计算单元。见 [第 5 章](./ch05-gpus-tpus)
- **算术强度（arithmetic intensity）**：每从内存读写一个字节能做多少次计算，决定一个运算受算力还是受带宽限制。见 [第 5 章](./ch05-gpus-tpus)
- **Roofline 模型（roofline model）**：以算术强度为横轴、可达性能为纵轴的「屋顶」图，一眼看出瓶颈在内存还是计算。见 [第 5 章](./ch05-gpus-tpus)
- **内存受限 / 计算受限（memory-bound / compute-bound）**：前者时间主要花在搬数据，后者主要花在计算，优化方向完全不同。见 [第 5 章](./ch05-gpus-tpus)
- **算子融合（operator / kernel fusion）**：把多个连续的小运算合成一个 kernel，省掉中间结果来回读写显存，类似减少重复的 layout pass。见 [第 5 章](./ch05-gpus-tpus)
- **重计算 / 激活检查点（recomputation / activation checkpointing）**：反向传播时重新算一遍激活值而不是一直存着，用算力换显存。见 [第 5 章](./ch05-gpus-tpus)
- **分块（tiling）**：把大矩阵切成能放进共享内存的小块分批计算，提高数据复用率。见 [第 5 章](./ch05-gpus-tpus)
- **FlashAttention**：用分块和在线 softmax 在片上完成注意力计算，不把巨大的注意力矩阵写回显存。见 [第 5 章](./ch05-gpus-tpus)
- **kernel（核函数）**：在 GPU 上并行执行的一段函数，PyTorch 的每个运算底层都对应一个或多个 kernel。见 [第 5 章](./ch05-gpus-tpus)
- **Triton**：OpenAI 推出的用 Python 写 GPU kernel 的语言，以「块」为单位思考，比 CUDA 简单。见 [第 6 章](./ch06-kernels-triton)
- **集合通信（collective communication）**：多张 GPU 之间按固定模式交换数据的操作，是分布式训练的「标准库」。见 [第 7 章](./ch07-parallelism-1)
- **all-reduce / reduce-scatter / all-gather**：分别是「所有卡求和后人人一份」「求和后每人一片」「把每人的一片拼成完整的人人一份」。见 [第 7 章](./ch07-parallelism-1)
- **数据并行（DP, Data Parallelism）**：每张卡放一份完整模型、处理不同数据，最后同步梯度。见 [第 7 章](./ch07-parallelism-1)
- **张量并行（TP, Tensor Parallelism）**：把每一层的大矩阵按宽度切到多张卡上一起算，通信频繁，通常只在机器内使用。见 [第 7 章](./ch07-parallelism-1)
- **流水线并行（PP, Pipeline Parallelism）**：按层把模型切成几段放到不同卡上，像流水线一样传递数据，首尾空等的「气泡」用微批次来缩小。见 [第 7 章](./ch07-parallelism-1)
- **ZeRO / FSDP（Fully Sharded Data Parallel）**：把优化器状态、梯度乃至参数都切片分散到各卡，用时再临时收集，大幅省显存。见 [第 8 章](./ch08-parallelism-2)
- **序列并行（sequence parallelism）**：沿序列长度方向切分激活值，进一步降低每张卡的激活显存。见 [第 8 章](./ch08-parallelism-2)
- **专家并行（EP, Expert Parallelism）**：把 MoE 的不同专家放在不同卡上，token 通过 all-to-all 通信被送到对应专家。见 [第 8 章](./ch08-parallelism-2)
- **预填充与解码（prefill / decode）**：推理的两个阶段，前者一次性处理整段提示（计算受限），后者逐个生成 token（内存受限）。见 [第 10 章](./ch10-inference)
- **量化（quantization）**：用更少的比特（如 8 位、4 位）表示权重或激活，换取更小的显存和更快的推理。见 [第 10 章](./ch10-inference)
- **推测解码（speculative decoding）**：用小模型先猜几个 token，再让大模型一次性验证，结果不变但更快。见 [第 10 章](./ch10-inference)
- **连续批处理（continuous batching）**：推理服务中请求随到随加入、完成随走，不必等一整批一起结束。见 [第 10 章](./ch10-inference)

## 四、缩放：缩放定律与超参数

- **缩放定律（scaling law）**：模型损失随参数量、数据量、算力增长而按幂律下降的经验规律，可以用小实验外推大模型表现，类似对 benchmark 做外推。见 [第 9 章](./ch09-scaling-laws-1)
- **幂律（power law）**：形如 $y = a x^{-b}$ 的关系，在 log-log 坐标下是一条直线。见 [第 9 章](./ch09-scaling-laws-1)
- **计算最优 / Chinchilla 定律（compute-optimal / Chinchilla）**：固定算力下参数量和数据量应同比例增长，经验上约每个参数配 20 个 token。见 [第 9 章](./ch09-scaling-laws-1)
- **IsoFLOP 曲线（IsoFLOP curve）**：固定总算力、改变模型大小画出的损失曲线，其最低点给出该算力下的最优模型大小。见 [第 9 章](./ch09-scaling-laws-1)
- **临界批大小（critical batch size）**：超过它后再增大批次基本不再加速训练的那个批大小。见 [第 9 章](./ch09-scaling-laws-1)
- **数据配比（data mixture）**：预训练数据中各来源（网页、代码、书籍等）所占的比例。见 [第 9 章](./ch09-scaling-laws-1)
- **最大更新参数化（μP, Maximal Update Parametrization）**：按宽度调整初始化和学习率的规则，让小模型上调好的超参数能直接迁移到大模型。见 [第 11 章](./ch11-scaling-laws-2)
- **WSD 学习率调度（Warmup-Stable-Decay）**：先预热、再长时间保持常数、最后快速衰减的学习率曲线，方便从中途分叉做不同长度的实验。见 [第 11 章](./ch11-scaling-laws-2)
- **Muon**：对矩阵参数的更新做正交化处理的新优化器，在一些大模型上替代了 AdamW。见 [第 11 章](./ch11-scaling-laws-2)
- **测试时扩展（test-time scaling）**：推理时让模型想得更久（更长的思维链），性能随之提升。见 [第 16 章](./ch16-rlvr)

## 五、数据与评估

- **基准测试（benchmark）**：一组标准化的题目和打分方式，用来比较不同模型的能力。见 [第 12 章](./ch12-evaluation)
- **数据污染（contamination）**：测试题提前出现在训练数据里，导致分数虚高。见 [第 12 章](./ch12-evaluation)
- **LLM 评委（LLM-as-a-judge）**：用一个强语言模型来给别的模型的回答打分或做成对比较。见 [第 12 章](./ch12-evaluation)
- **思维链（CoT, Chain of Thought）**：让模型在给出答案前先一步步写出推理过程。见 [第 12 章](./ch12-evaluation)
- **Common Crawl**：一个定期抓取全网网页并公开快照的非营利项目，几乎所有开源预训练数据的源头。见 [第 13 章](./ch13-data-sources)
- **质量过滤（quality filtering）**：用规则或分类器从海量网页中筛出「像高质量文本」的部分。见 [第 13 章](./ch13-data-sources)
- **合成数据（synthetic data）**：由模型生成而非人类撰写的训练数据，在中训练和后训练中大量使用。见 [第 13 章](./ch13-data-sources)
- **预训练 / 中训练 / 后训练（pre-training / mid-training / post-training）**：训练的三个阶段，分别对应海量通用数据、高质量与指令数据混入衰减期、对齐与能力塑形。见 [第 13 章](./ch13-data-sources)
- **去重（deduplication）**：删除完全相同或高度相似的文档，避免模型反复背诵同一内容。见 [第 14 章](./ch14-data-processing)
- **MinHash / 局部敏感哈希（MinHash / LSH）**：用少量哈希值快速估计两篇文档的相似度，实现大规模近似去重。见 [第 14 章](./ch14-data-processing)

## 六、后训练、强化学习与多模态

- **监督微调（SFT, Supervised Fine-Tuning）**：在「指令 → 理想回答」数据上继续做下一个 token 预测，教模型如何回答。见 [第 15 章](./ch15-mid-post-training)
- **指令遵循（instruction following）**：模型理解并执行复杂、长篇指令的能力，后训练要解锁的核心能力。见 [第 15 章](./ch15-mid-post-training)
- **对话模板（chat template）**：用特殊标记把系统提示、用户和助手的多轮对话拼成一条训练序列的格式。见 [第 15 章](./ch15-mid-post-training)
- **损失掩码（loss mask）**：标记哪些 token 计入损失，SFT 时通常只在助手回答上算损失。见 [第 15 章](./ch15-mid-post-training)
- **蒸馏（distillation）**：用更强模型生成的输出来训练较弱或较小的模型，让后者学会前者的行为。见 [第 15 章](./ch15-mid-post-training)
- **幻觉（hallucination）**：模型自信地编造不存在的事实或引用。见 [第 15 章](./ch15-mid-post-training)
- **基于人类反馈的强化学习（RLHF, Reinforcement Learning from Human Feedback）**：先收集人类的偏好（通常是「两个回答选一个更好的」），训练奖励模型，再用强化学习让模型最大化该奖励。见 [第 15 章](./ch15-mid-post-training)
- **AI 反馈（AI feedback / RLAIF）**：用模型代替人类做偏好标注，成本低一个数量级，如今是开源后训练的主流。见 [第 15 章](./ch15-mid-post-training)
- **奖励模型（RM, Reward Model）**：输入提示和回答、输出一个分数的模型，用来代替人类给回答打分。见 [第 15 章](./ch15-mid-post-training)
- **Bradley-Terry 模型（Bradley-Terry model）**：假设「A 胜过 B 的概率 = sigmoid(A 的分 − B 的分)」，用来从成对偏好中学出奖励分数。见 [第 15 章](./ch15-mid-post-training)
- **策略（policy）**：强化学习中「给定状态如何选动作」的规则，在 LLM 里就是模型本身。见 [第 15 章](./ch15-mid-post-training)
- **策略梯度（policy gradient）**：用「奖励 × 对数概率的梯度」来更新策略，相当于按奖励加权的 SFT。见 [第 15 章](./ch15-mid-post-training)
- **KL 散度（KL divergence）**：衡量两个概率分布差多远的量，RLHF 用它把模型拴在参考模型附近。见 [第 15 章](./ch15-mid-post-training)
- **参考模型（reference model）**：RLHF / DPO 中冻结不动的初始模型（通常是 SFT 后的模型），作为「别跑太远」的锚点。见 [第 15 章](./ch15-mid-post-training)
- **在线策略 / 离线策略（on-policy / off-policy）**：前者只用当前模型刚采样的数据更新，后者复用旧模型或别处来的数据。见 [第 15 章](./ch15-mid-post-training)
- **近端策略优化（PPO, Proximal Policy Optimization）**：通过裁剪新旧策略的概率比来限制每步更新幅度的强化学习算法，效果好但难调。见 [第 15 章](./ch15-mid-post-training)
- **直接偏好优化（DPO, Direct Preference Optimization）**：不训练奖励模型、不采样，直接在偏好对上「推高赢家、压低输家」的 RLHF 替代方法。见 [第 15 章](./ch15-mid-post-training)
- **过度优化（overoptimization）**：一味最大化学到的奖励模型分数，代理分数还在涨，真实质量却开始下降，即古德哈特定律。见 [第 15 章](./ch15-mid-post-training)
- **模式坍缩（mode collapse）**：RL 后模型输出多样性大幅下降、集中到少数几种答案，并且不再校准。见 [第 15 章](./ch15-mid-post-training)
- **可验证奖励强化学习（RLVR, Reinforcement Learning from Verifiable Rewards）**：用程序就能判定对错的奖励（数学答案、单元测试）做强化学习，可以持续加算力而不怕过拟合奖励模型。见 [第 16 章](./ch16-rlvr)
- **优势（advantage）**：一个回答的奖励比「预期」好多少，策略梯度用它代替原始奖励来降低方差。见 [第 16 章](./ch16-rlvr)
- **基线（baseline）**：从奖励中减去的参考值（只依赖于提示），不改变梯度期望方向但能降低方差。见 [第 16 章](./ch16-rlvr)
- **价值模型（value model）**：PPO 中预测「从当前位置开始预期能得多少奖励」的网络，和策略模型一样大。见 [第 16 章](./ch16-rlvr)
- **组相对策略优化（GRPO, Group Relative Policy Optimization）**：对同一题采样一组回答，用组内 z 分数代替价值模型来计算优势的 PPO 简化版。见 [第 16 章](./ch16-rlvr)
- **Dr. GRPO**：去掉 GRPO 中「除以标准差」和「按回答长度归一化」两项的修正版，消除了长度膨胀等偏差。见 [第 16 章](./ch16-rlvr)
- **结果监督 / 过程监督（outcome / process supervision）**：前者只按最终答案对错给奖励，后者对每个推理步骤打分（过程奖励模型 PRM）。见 [第 16 章](./ch16-rlvr)
- **拒绝采样微调 / 专家迭代（RFT / expert iteration）**：反复「采样 → 只保留答对的 → 在其上做 SFT」，是 RL 的简单基线。见 [第 16 章](./ch16-rlvr)
- **奖励被钻空子（reward hacking）**：模型找到奖励函数的漏洞来拿高分而不是真正完成任务，例如偷看 git 历史里的答案。见 [第 16 章](./ch16-rlvr)
- **多模态 / 全模态模型（multimodal / omni model）**：能理解（乃至生成）文字之外的图像、音频、视频的模型，全模态指任意输入到任意输出。见 [第 17 章](./ch17-alignment-multimodality)
- **视觉 Transformer（ViT, Vision Transformer）**：把图片切成固定大小的小方块（patch），每块当作一个 token 送进 Transformer。见 [第 17 章](./ch17-alignment-multimodality)
- **CLIP（Contrastive Language-Image Pre-training）**：在 4 亿图文对上做对比学习（让配对的图文向量靠近、不配对的远离）得到的图文编码器，能零样本分类，是多数 VLM 的视觉基础。见 [第 17 章](./ch17-alignment-multimodality)
- **SigLIP**：把 CLIP 的全批次 softmax 换成逐对 sigmoid 二分类的改进版，更省、更易并行、与批大小解耦。见 [第 17 章](./ch17-alignment-multimodality)
- **视觉语言模型（VLM, Vision-Language Model）**：视觉编码器 + 适配器 + 语言模型组成、能看图回答问题的模型。见 [第 17 章](./ch17-alignment-multimodality)
- **适配器 / 投影器（adapter / projector）**：把视觉编码器输出的向量映射到语言模型词嵌入空间的小网络（线性层或 MLP）。见 [第 17 章](./ch17-alignment-multimodality)
- **AnyRes / 动态分辨率（dynamic resolution）**：不把图片硬缩成固定尺寸，而是切块或按原比例编码，token 数随分辨率变化，保留 OCR 所需的细节。见 [第 17 章](./ch17-alignment-multimodality)
- **多模态旋转位置编码（M-RoPE, Multimodal RoPE）**：把 RoPE 扩展到时间、高、宽三个维度，表示图像和视频 token 的位置。见 [第 17 章](./ch17-alignment-multimodality)
- **VQ-VAE（Vector Quantized Variational Autoencoder）**：把图像编码后「四舍五入」到码本中最近的码字，从而得到离散的图像 token。见 [第 17 章](./ch17-alignment-multimodality)
- **扩散模型（diffusion model）**：从噪声出发逐步去噪生成图像的模型，擅长还原精细细节，是图像生成的主流方法。见 [第 17 章](./ch17-alignment-multimodality)
