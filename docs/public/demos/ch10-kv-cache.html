推理的两个阶段：Prefill（预填充）与 Decode（逐个生成）

① 动画：KV cache 是怎么长出来的

② 显存与速度计算器（每生成一个 token）

显存占用（蓝 = 参数，紫 = KV cache；竖线 = 显存上限）
batch 大小 B 的权衡：每 token 延迟（橙）与吞吐（绿）。灰色区域 = 显存放不下。圆点 = 当前 B。
公式（与讲义一致，只计矩阵乘法、bf16 参数）：参数量 = 2VD + 3DFL + (2DNH + 2DKH)L；每 token 的 KV = 2(K 和 V) × K × H × L × 字节数； Decode 阶段受显存带宽限制：每步要把“全部参数 + 全部 KV cache”从 HBM 读一遍，所以 延迟 ≈ (参数字节 + B × S × 每 token KV) ÷ 带宽，吞吐 = B ÷ 延迟。 动画里每个阶段的耗时取 max(FLOPs ÷ 算力, 字节 ÷ 带宽)。
